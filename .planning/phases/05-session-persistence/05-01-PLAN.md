## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Plugin process → local disk (ConfigDirectory/scan-cache.json) | Local filesystem; only this plugin reads/writes. No network, no auth, no untrusted external input. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-01 | Tampering | scan-cache.json on disk | accept | Local-only convenience cache. Tampered Bought/Listed dictionaries only mis-color checkboxes for the player who tampered with their own file; no other user impact. |
| T-05-02 | Denial of Service | scan-cache.json deserialize | mitigate | LoadAnyAsync wraps deserialization in try/catch on `IOException or JsonException or UnauthorizedAccessException` and returns null on any failure (already implemented). Malformed JSON triggers a fresh scan, not a crash. |
| T-05-03 | Information Disclosure | scan-cache.json contents | accept | File contains only public market-board prices and item ids — no PII, no credentials, no game account data. |
| T-05-04 | Tampering (path traversal) | cachePath construction | mitigate | Filename is the const `"scan-cache.json"`; directory is `pluginInterface.ConfigDirectory.FullName` (Dalamud-managed). User input does not influence the path. |
| T-05-05 | Denial of Service | concurrent overlapping saves | mitigate | SemaphoreSlim(1,1) inside ScanCacheStore serializes SaveSessionAsync calls (D-05). Last-write-wins is acceptable per D-05 because state is monotonic per click. |
| T-05-06 | Repudiation | save failure | accept | Per D-06, save failures log a warning and continue; the next successful click rewrites the dictionaries idempotently. No audit log needed for a single-player local convenience cache. |

Security surface for Phase 5 is intentionally minimal: local JSON file in a Dalamud-managed
directory, no network, no auth, no untrusted-input parsing. ASVS L1 not applicable beyond
the existing exception-filtered I/O guards.

3. Add a new public method placed AFTER `SaveAsync` (after line 85's closing brace) and BEFORE
   `CreateConfigFingerprint`:

```csharp
public async Task SaveSessionAsync(SessionState sessionState, CancellationToken ct = default)
{
    ArgumentNullException.ThrowIfNull(sessionState);

    await sessionSaveLock.WaitAsync(ct);
    try
    {
        var envelope = await LoadAnyAsync(ct);
        if (envelope == null)
            return;  // No envelope on disk yet — nothing to persist session into. Next SaveAsync (after a scan) writes a fresh envelope with empty SessionState; the next click will then succeed.

        envelope.SessionState = sessionState;

        var tempPath = cachePath + ".tmp";
        await using (var stream = File.Create(tempPath))
        {
            await JsonSerializer.SerializeAsync(
                stream,
                envelope,
                ApiJsonContext.Default.ScanCacheEnvelope,
                ct);
        }

        File.Move(tempPath, cachePath, overwrite: true);
    }
    catch (Exception ex) when (ex is IOException or JsonException or UnauthorizedAccessException)
    {
        log.Warning("/nflip: could not save session state: {Message}", ex.Message);
    }
    finally
    {
        sessionSaveLock.Release();
    }
}
```

Notes for the executor:
- The exception filter `(IOException or JsonException or UnauthorizedAccessException)` MATCHES
  the filter used in LoadAnyAsync (line 54). This is intentional — same three failure modes
  (disk full, AV-locked file, permission denied), same silent-warning response (D-06).
- The `await sessionSaveLock.WaitAsync(ct)` BEFORE the try block, with `sessionSaveLock.Release()`
  in `finally`, prevents two overlapping fire-and-forget saves from racing on the temp file.
  Last-write-wins is acceptable per D-05.
- The `if (envelope == null) return;` early-out handles the edge case of a save dispatched
  before the first scan has written an envelope — extremely unlikely (the UI is hidden until a
  scan succeeds) but defensively cheap.

/// Queue a fire-and-forget save of the current bought/listed dictionaries to disk.
/// Called from DailyRouteWindow checkbox handlers and Mark All buttons (D-04, D-05).
/// </summary>
public void QueueSessionSave(Dictionary<int, bool> bought, Dictionary<int, bool> listed)
{
    // Snapshot the dictionaries off the UI thread so the background save sees a stable view.
    var snapshot = new SessionState
    {
        Bought = new Dictionary<int, bool>(bought),

        }
        catch (OperationCanceledException)

        }

}
