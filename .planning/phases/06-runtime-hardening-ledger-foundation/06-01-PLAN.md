# 06-01 Plan: Runtime Hardening & Ledger Foundation

## Objective

Implement Phase 6 as one bundled plan: harden scan/session persistence and introduce durable bought-lot ledger records without adding sold-entry or profit-history workflows.

## Tasks

1. Serialize all `scan-cache.json` writes through one write gate and one atomic replacement helper.
2. Fix cache fingerprinting so every scan-affecting setting, including `MinSalesPerDay`, invalidates stale cache results.
3. Make route/session/ledger-mutating UI actions deterministic during in-flight scans.
4. Remove or scope temporary runtime diagnostics so release builds do not suppress unrelated failures or emit periodic heartbeat noise.
5. Add structured scan warning data and compact warning rendering.
6. Add an independent versioned `flip-ledger.json` store with backup-on-write.
7. Add bought-lot records with identity, buy date, actual buy price, planned sell/profit, quantity lifecycle fields, status, and route/session trace.
8. Add mark-bought confirmation with editable quantity and actual unit buy price.
9. Add minimal open positions correction/delete UI.
10. Add/update source-validation scripts for Phase 6 and stale Phase 3/5 assertions.

## Acceptance

- Source validation passes for Phases 3, 4, 5, and 6.
- GitHub Actions build passes on the draft PR.
- No sold-state or profit-history functionality is introduced before Phase 7.
- Ledger records persist independently of scan-cache freshness.
