<threat_model>
T-03-04: Route ordering could over-optimize travel and send users to low-value stops first. Mitigation: total expected value is primary; travel friction is only a tie-breaker inside the 20% value window.

T-03-05: Cache reuse could show stale or wrong-config results as fresh. Mitigation: cache validity requires matching schema version, unexpired timestamp, and matching scan-affecting config fingerprint.

T-03-06: Manual rescan and login auto-scan could run concurrently and corrupt latest-result/cache state. Mitigation: add a duplicate-scan guard with cancellation/disposal discipline.

T-03-07: Login-time scanning before character readiness could fail noisily or run at title screen. Mitigation: use `IClientState.Login`, startup `IsLoggedIn`, and skip when required config is missing.
</threat_model>

<decision_coverage>
- D-01: Bare `/nflip` remains the UI toggle.
- D-02: `/nflip scan` is added as an explicit manual scan command for Phase 3 testing.
- D-03: Normal scan output is concise: status, route stop count, opportunity count, and total expected profit.
- D-04: Duplicate scans are ignored with a clear `scan already running` log.
- D-05: `LatestScanResult` stores the latest route in memory for Phase 4.
- D-06: Character login uses `IClientState.Login`; title screen and character select are not scan triggers.
- D-07: Startup checks `IClientState.IsLoggedIn` for already-logged-in plugin loads.
- D-08: Login/plugin-ready scan first loads valid cache, otherwise scans when required config exists.
- D-09: Missing home world skips auto-scan and logs the setup requirement.
- D-10: `/nflip scan` passes `forceRefresh: true` and always bypasses cache.
- D-16: Route optimization favors a runnable route over theoretical maximum profit.
- D-17: `MaxServersToVisit` is enforced at the stop-selection layer before final item trimming.
- D-18: One-item stops are allowed when they fit the stop cap.
- D-19: Vendor sources become distinct non-world route stops.
- D-21: Route stops are ordered by highest total expected value first.
- D-22: Data center boundaries are ignored when value differences exceed the 20% tie-break window.
- D-23: Travel friction is only a tie-breaker when stop values are within about 20%.
- D-24: `WorldData` adds a hardcoded world-to-data-center map.
- D-25: Phase 3 implements a file-backed scan cache.
- D-26: Cache stores both raw scan response and derived route.
- D-27: Cache invalidates by age, config fingerprint, and schema version.
- D-28: Cache is stored under `IDalamudPluginInterface.ConfigDirectory`, not in `Configuration` or the repository.
- D-29: Manual `/nflip scan` fetches fresh results and writes a fresh cache on success.
- D-30: Valid cached/latest results are available for Phase 4 without forcing an API call.
- D-31: Refresh failure falls back to previous cache when available.
- D-32: Stale fallback is marked with `UsingStaleCache` and `IsFresh = false`.
- D-33: Successful-but-empty scan results remain `Empty` and do not reuse old route data.
- D-34: Previous cache is not reused after successful-but-empty scans.
- D-35: The cache/route path does not relax thresholds automatically.
- D-36: If no usable cache exists after failure, the result remains a structured `Error`.
