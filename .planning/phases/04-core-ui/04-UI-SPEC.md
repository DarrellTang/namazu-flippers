| Property | Value |
|----------|-------|

## Layout Primitives

### Spacing (ImGui frame units)

ImGui spacing is expressed in screen pixels via `ImGui.SetCursorPosY`, `ImGui.Dummy`, and `ImGui.Spacing`. Use multiples of 4 to maintain visual rhythm.

| Usage | Pixels | ImGui Call |
|-------|--------|------------|
| Inline icon gap | 4 | `ImGui.SameLine(0, 4)` |
| Compact item row gap | 4 | `ImGui.Spacing()` (default frame spacing ≈4) |
| Between sections (server stops) | 8 | `ImGui.Dummy(new Vector2(0, 4))` + `ImGui.Separator()` |
| Header-to-content padding | 8 | ImGui CollapsingHeader built-in indent |
| Progress bar height | 16 | `ImGui.ProgressBar(fraction, new Vector2(-1, 16))` |
| Confirm button width | 120 | matches FirstRunWindow.cs precedent |

**No 8-point CSS grid — ImGui item spacing is set via `ImGui.PushStyleVar(ImGuiStyleVar.ItemSpacing, ...)`.**
Override item spacing only within tightly-spaced item lists; restore immediately after.

### Layout Structure (DailyRouteWindow)

```
┌─ Window titlebar: "Namazu Flippers — Daily Route" ─────────┐
│  [Status banner — conditional, see Status States]           │
│  ─────────────────────────────────────────────────          │
│  Progress: Bought X/N  Listed X/N   [Rescan Route button]  │
│  ProgressBar (bought fraction, green)                        │
│  ProgressBar (listed fraction, cyan)                         │
│  Profit tally: X,XXX,XXX gil expected today                 │
│  ─────────────────────────────────────────────────          │
│  ▼ [Server Stop Label]  — e.g. "Midgardsormr (Aether)"     │
│     □ Item Name   Buy: X,XXX   Sell: X,XXX   +X,XXX/day    │
│     □ Item Name   [OOS] Buy at vendor                       │
│  ▶ [Completed stop — collapsed]                             │
│  ─────────────────────────────────────────────────          │
│  ▼ Home: [HomeWorld]                                        │
│     □ Item Name   List for: X,XXX                           │
└─────────────────────────────────────────────────────────────┘
```

**Primary focal point:** the progress summary section (progress bars + profit tally) is the first fixed element the eye lands on after the status banner — it answers "how much have I done and how much will I earn?" in a single glance. The executor must render this section before the server stop list, never after.

### Layout Structure (ConfigWindow)

```
┌─ Namazu Flippers — Settings ────────────────────────────────┐
│  ► Home World        [dropdown: current world]              │
│  ► Profit Thresholds [sliders / int inputs]                 │
│  ► Velocity          [sliders / int inputs]                 │
│  ► Route Caps        [int inputs]                           │
│  ► Filters           [checkboxes: region, categories, etc.] │
│  ► Cache             [int input: cache hours]               │
│  ─────────────────────────────────────────────────          │
│  [Save Settings]   [Reset to Defaults]                      │
└─────────────────────────────────────────────────────────────┘
```

Use `ImGui.CollapsingHeader` for each settings group. Default all open.

## Typography

ImGui uses a single embedded font (Dalamud's ProggyClean/Noto default). Custom font loading is not in scope for Phase 4.

| Role | Size | Mechanism | Line Height |
|------|------|-----------|-------------|
| Body / item row | Default (13px equivalent) | `ImGui.Text` | ImGui default (1.0 leading + frame padding) |
| Section label / stop header | Default | `ImGui.CollapsingHeader` (which already renders heavier than body text); section emphasis comes from **color + separator**, not weight | ImGui default |
| Profit tally / total | Default | `ImGui.TextColored(GilGold, ...)` for value, plain for label | ImGui default |
| Status banner | Default | `ImGui.TextWrapped` | ImGui default (wraps at window width) |

**No custom font pairs, no rem units, no line-height CSS values.** Typography is controlled entirely by ImGui's built-in font atlas.

**No bold variant in stock Dalamud.** `UiBuilder` exposes `DefaultFont`, `IconFont`, and `MonoFont` only — there is no `BoldFont`. Section emphasis is achieved through (1) `CollapsingHeader`'s built-in heavier rendering and indent affordance, (2) `TextColored` for high-contrast values like gil amounts, and (3) `Separator()` to delineate sections. Do **not** attempt to load a custom bold font in Phase 4 — the visual hierarchy is sufficient without it.

## Color

ImGui renders in the host application's FFXIV theme. Phase 4 overlays semantic meaning with `ImGui.TextColored(Vector4 color, string text)`.

All colors declared as `Vector4(R, G, B, A)` — alpha=1.0f unless noted.

| Role | Vector4 | Hex Approx | Reserved For |
|------|---------|-----------|--------------|
| Default text | ImGui theme default | — | All unlabeled text |
| GilGold (accent) | `(1.0f, 0.85f, 0.1f, 1.0f)` | #FFD91A | Gil amounts (`ExpectedDailyProfit`, `TotalExpectedDailyProfit`, `HomePrice`, profit tally display) |
| PurchaseCyan | `(0.2f, 0.85f, 0.9f, 1.0f)` | #33D9E6 | Purchase prices (`PurchasePrice`) and "Buy:" label |
| VendorCyan | `(0.2f, 0.85f, 0.9f, 1.0f)` | #33D9E6 | Vendor stop labels and "Sold by vendor" text (same as PurchaseCyan — vendor is a buy action) |
| OosOrange | `(1.0f, 0.55f, 0.1f, 1.0f)` | #FF8C1A | OOS badge, OOS item name text, and the [OOS] icon; also priority indicator |
| StaleAmber | `(0.9f, 0.7f, 0.1f, 1.0f)` | #E6B21A | "Using stale cache" status banner background tint |
| ErrorRed | `(0.9f, 0.2f, 0.2f, 1.0f)` | #E63333 | Error status banner text; destructive actions |
| SuccessGreen | `(0.2f, 0.8f, 0.3f, 1.0f)` | #33CC4D | Bought progress bar fill; "all items bought" completion state |
| CompletedGray | `(0.5f, 0.5f, 0.5f, 0.7f)` | #808080 at 70% | Checked/bought item name text (dimmed); auto-collapsed stop header |
| CacheBlue | `(0.4f, 0.7f, 1.0f, 1.0f)` | #66B2FF | "Using cache" status banner text (neutral info) |

**Color usage rules:**
- GilGold: gil amounts only. Never use for item names, server labels, or non-monetary text.
- OosOrange: OOS items only. Never use for non-OOS items regardless of other priority.
- PurchaseCyan / VendorCyan: buy-side prices and vendor labels only. Never for sell/list prices.
- ErrorRed: error banners and `Reset to Defaults` destructive button only.
- CompletedGray: item name after checkbox ticked (bought or listed). Gives struck-through feel without text-decoration (not available in ImGui).
- CacheBlue: only the "Using cached route from HH:MM" status banner.
- StaleAmber: only the "Stale cache" warning banner.

## Status States

The `ScanEngineStatus` enum drives the top-of-window banner. All five states must be handled.

| Status | Banner Behavior | Color | Copy |
|--------|----------------|-------|------|
| `Success` | No banner (route is fresh, no notification needed) | — | — |
| `UsingCache` | Single-line info bar | CacheBlue text | `Using cached route from {HH:MM}. /nflip scan to refresh.` |
| `UsingStaleCache` | Prominent warning bar | StaleAmber background, dark text | `Route is outdated. /nflip scan to refresh.` |
| `Empty` | Single-line notice | Default | `No opportunities matched your current settings.` |
| `Error` | Error bar | ErrorRed text | From `result.UserMessage` (friendly string set by ScanEngine) |
| `null` (no scan yet) | Loading / waiting notice | Default | `Scanning for opportunities... (or /nflip scan to start)` |

Banner implementation: `ImGui.PushStyleColor` + `ImGui.TextWrapped` + `ImGui.PopStyleColor`. For `UsingStaleCache`, push a background color on a child region or use a colored text prefix icon.

## Interaction Contracts

### Checkbox: Bought

- Trigger: user clicks `ImGui.Checkbox` on a route item.
- Effect: item's `bought` state flips; item name dimmed to CompletedGray; profit tally updates.
- Auto-collapse: when all items in a `RouteStop` have `bought == true`, `CollapsingHeader` header is set to `open = false`. The header remains visible but collapsed; item count and total profit shown in the collapsed label.
- Source: UI-02, UI-07.

### Checkbox: Listed

- Trigger: user clicks listed checkbox on home stop item.
- Effect: item's `listed` state flips; listed progress bar and listed profit tally update.
- Source: UI-03, UI-04.

### Rescan Route Button

- Label: `Rescan Route`
- Placement: right-aligned in the summary section (use `ImGui.SetCursorPosX(ImGui.GetContentRegionAvail().X - buttonWidth)` before drawing).
- Behavior: calls `RunScanAsync(forceRefresh: true)` via plugin reference. Disabled (`ImGui.BeginDisabled()`) while `scanInProgress == 1`.
- After scan: `LatestScanResult` on the plugin is updated; window re-reads it next frame.
- Source: SCAN-04.

### Auto-collapse on completion

- When all `RouteStop.Items` have `bought == true`: collapse that stop's `CollapsingHeader` **once**, on the frame the condition first becomes true. Do not force re-collapse on subsequent frames — the user must remain able to re-expand the stop to inspect what they bought.
- **Mechanism:** maintain a per-stop "has-auto-collapsed" flag in the window state (e.g., `Dictionary<string, bool> autoCollapsedStops` keyed by `PurchaseSource`). On each draw, if `allBought == true` AND `autoCollapsedStops[source] == false`, call `ImGui.SetNextItemOpen(false, ImGuiCond.Always)` before the `CollapsingHeader` and set the flag to `true`. If `allBought` flips back to `false` (user unchecks an item), reset the flag to `false` so the next completion will trigger collapse again.
- Do **not** use the `ref bool` overload of `CollapsingHeader` for this — that parameter controls the close-button (X) visibility, not the open/closed state. ImGui has no direct "set open" API on the header itself; `SetNextItemOpen` is the only correct mechanism.
- Collapsed label format: `✓ {PurchaseSource} — {N} items — {total profit:n0} gil/day`.
- CompletedGray color on collapsed header label (apply via `PushStyleColor(ImGuiCol.Text, CompletedGray)` around the `CollapsingHeader` call).
- Source: UI-07.

### Tooltips

- Every item row shows a tooltip on hover: `Avg {SalesPerDay:F1} sales/day`.
- Config fields show tooltips explaining what each setting does (described in Widget Inventory above).
- Tooltip for MaxBudgetPerItem = 0: `Set to 0 to disable the budget cap`.
- Tooltips implemented via `ImGui.IsItemHovered() → ImGui.BeginTooltip() / ImGui.EndTooltip()`.

### Vendor stops

- Vendor stops render the same `CollapsingHeader` + item list structure as world stops.
- Stop header label: `Vendor: {PurchaseSource}` in VendorCyan.
- No travel context (no DC label, no hop count) for vendor stops.
- Item rows in vendor stops suppress the "Buy:" price column (vendor NPC price is implicit or listed in name).
- Source: D-19 (03-CONTEXT.md).

## Visual Density

Density target: **compact** — fit 10 items across up to 10 server stops in a 560px-tall window without scrolling for a typical 5-stop, 10-item route.

- `ImGui.PushStyleVar(ImGuiStyleVar.ItemSpacing, new Vector2(4, 4))` within item lists; restore after each stop.
- Default frame padding elsewhere — do not alter globally.
- One `ImGui.Spacing()` between server stops (adds ~4px vertical gap before the next separator).
- Scrollable window content via `ImGui.BeginChild("route-scroll", scrollSize, false)` if content exceeds window height — enable inner scrollbar, not outer window scroll.

## State the UI Reads (Phase 4 only — bought/listed live in memory)

Phase 5 adds JSON persistence. In Phase 4, bought/listed state lives in the window class as `Dictionary<int, bool>` keyed by `ItemId`. The window initializes from `LatestScanResult` on each draw if `LatestScanResult` changed.

| State | Type | Owned By |
|-------|------|----------|
| `LatestScanResult` | `ScanEngineResult?` | `NamazuFlippers` plugin (already exists) |
| `scanInProgress` | `int` (0/1) | `NamazuFlippers` plugin (already exists) |
| `boughtState` | `Dictionary<int, bool>` keyed by `ItemId` | `DailyRouteWindow` |
| `listedState` | `Dictionary<int, bool>` keyed by `ItemId` | `DailyRouteWindow` |
| `autoCollapsedStops` | `Dictionary<string, bool>` keyed by `RouteStop.PurchaseSource` — flips true when stop first becomes all-bought, flips false if any item is unchecked | `DailyRouteWindow` |
| Config | `Configuration` | `NamazuFlippers.Configuration` |
