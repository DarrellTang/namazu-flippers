**Replace with:**
```csharp
ImGui.SameLine();
const float rescanWidth = 110f;
const float settingsWidth = 80f;
// Source the gap from runtime ImGui style so it tracks Dalamud's UI scale —
// the SameLine() between Settings and Rescan below uses this same value.
// (Hardcoding 8f overflowed Rescan past the right edge at FFXIV UI scale > 1.0;

var buttonSpacing = ImGui.GetStyle().ItemSpacing.X;
var avail = ImGui.GetContentRegionAvail().X;
var combinedWidth = rescanWidth + buttonSpacing + settingsWidth;
if (avail > combinedWidth)

```

**Why this is correct:** `ImGui.SameLine()` with no offset advances the cursor by `GetStyle().ItemSpacing.X`. Reading the same value into `buttonSpacing` means the reserved width matches the actual gap that will be inserted. At scale 1.0, behavior is unchanged (8 == 8). At scale 1.5, both the reservation and the actual gap become 12, so Rescan's right edge lands at exactly `content_right`, not `content_right + 4`. The behavior of the surrounding Settings/Rescan rendering, the BeginDisabled/EndDisabled guard, the click handlers, and all other code in `DrawProgressSection` MUST remain byte-for-byte identical. **Replace with:**
```csharp
ImGui.SameLine();
ImGui.TextColored(PurchaseCyan, $"Buy: {item.PurchasePrice:n0}");
ImGui.SameLine();
ImGui.TextColored(GilGold, $"+{item.ExpectedDailyProfit:n0}/day");

// Anchor the Listed checkbox + price label to a fixed X column right-aligned
// inside the row, so the checkbox lands in the same column on every item
// regardless of name length / [OOS] / [Vendor] / price / profit text widths.
// Computing the X each frame from GetContentRegionMax keeps the column resilient
// if the window is later resized; window is currently locked at 420px width.
// Width budget for the trailing column = checkbox (~22 px) + ItemSpacing
// (~8 px scaled) + "List: 9,999,999" worst-case label (~120 px) ≈ 150 px.
const float listedColumnWidth = 150f;
var rowCursorPosX = ImGui.GetCursorPosX();
var contentMaxX = ImGui.GetWindowContentRegionMax().X;
var listedAnchorX = contentMaxX - listedColumnWidth;
// Fall back to bare SameLine() if the row is too narrow to honor the anchor —
// prevents the checkbox from jumping LEFT into the prior text on a too-narrow row.
if (listedAnchorX > rowCursorPosX)
    ImGui.SameLine(listedAnchorX);
else
    ImGui.SameLine();
var listed = listedState.GetValueOrDefault(item.ItemId);
if (ImGui.Checkbox($"##listed-{item.ItemId}", ref listed))
    listedState[item.ItemId] = listed;
ImGui.SameLine();
ImGui.TextColored(GilGold, $"List: {item.HomePrice:n0}");
```

**Why this is correct:**
- `ImGui.SameLine(offset_from_start_x)` with a positive `offset_from_start_x` sets the cursor to that absolute X coordinate within the current window (relative to window content origin), not an offset from the previous widget. This is exactly what we need — a fixed column anchor.
- `GetWindowContentRegionMax().X - listedColumnWidth` right-aligns the trailing column. At 420 px window width with default padding, content_region_max.X ≈ 404, so anchor X ≈ 254. Every item row places its `##listed-` checkbox at X ≈ 254 regardless of preceding widget widths.
- The fallback `else { ImGui.SameLine(); }` preserves the old behavior on a row whose accumulated width already exceeds the anchor — guarantees the checkbox never jumps backward and overlaps prior text.
- The behavioral wiring (the `Checkbox` call, the `listedState[item.ItemId] = listed` dictionary update, and the `"List:"` label on the trailing line) is preserved verbatim. Only the X positioning logic before the checkbox changes.
- The Bought-checkbox column at the start of the row is also untouched.
