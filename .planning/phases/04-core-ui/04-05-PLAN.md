misreading.** No UI-SPEC update is required. The constructor and UI-SPEC both lock
the same dimensions. The bug is purely in the cursor arithmetic in DrawProgressSection.

disabled-during-scan guard is preserved.

Replacement code:
```csharp
ImGui.SameLine();
const float rescanWidth = 110f;
const float settingsWidth = 80f;
const float buttonSpacing = 8f; // ImGui default item spacing
var avail = ImGui.GetContentRegionAvail().X;
var combinedWidth = rescanWidth + buttonSpacing + settingsWidth;
if (avail > combinedWidth)
    ImGui.SetCursorPosX(ImGui.GetCursorPosX() + avail - combinedWidth);

// Settings button (D-07) — second entry point alongside UiBuilder.OpenConfigUi.
// Rendered FIRST (leftmost of the right-aligned pair) so Rescan ends up at the
// window's right edge and Settings sits inside the content region beside it.
if (ImGui.Button("Settings", new Vector2(settingsWidth, 0)))
    plugin.OpenConfigWindow();

ImGui.SameLine();
if (plugin.ScanInProgress)
    ImGui.BeginDisabled();
if (ImGui.Button("Rescan Route", new Vector2(rescanWidth, 0)))
    _ = plugin.RescanAsync(CancellationToken.None);
if (plugin.ScanInProgress)
    ImGui.EndDisabled();
```

**Layout math sanity check (do not skip):**
- Window width: 420px
- Approx content region after window padding (~16px each side): ≈ 388px
- Combined button width: 110 + 8 + 80 = 198px
- After "Bought: X/X   Listed: X/X" text, available content region is roughly
  388 - 200 (text) ≈ 188px in the worst case — but the text only consumes one line
  before SameLine; actual available `GetContentRegionAvail().X` after SameLine is
  approximately 388 - cursor_x_after_text. With short labels (e.g., "Bought: 0/0")
  the available is ample. With long labels (e.g., "Bought: 999/999  Listed: 999/999")
  the text could be ~20 chars; even so ~270px+ remain — comfortably > 198px.
- The `if (avail > combinedWidth)` guard means: if the text is too wide to leave
  room for both buttons, the buttons fall back to where the cursor sits after the
  text. This avoids negative SetCursorPosX. (This matches the original code's
  defensive `if (avail > buttonWidth)` pattern.)

**Why Settings rendered first (not Rescan first):**
The right-alignment cursor is set to `cursor + avail - combinedWidth`. The first
widget drawn at that cursor consumes 80px (Settings). Then `SameLine` adds
default spacing (~8px) and the next widget (Rescan, 110px) renders. Settings
ends at `cursor + avail - combinedWidth + 80 = cursor + avail - 118`.
Rescan ends at `cursor + avail - 118 + 8 + 110 = cursor + avail` — exactly at
the right edge of the content region. Both buttons fit inside. Visually, Settings
is to the left of Rescan, which matches the user's mental model of
"navigation/secondary action" sitting beside "primary action".
